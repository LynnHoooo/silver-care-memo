## 1. 项目定位与目标用户

| 角色 | 使用场景 | 核心诉求 |
| --- | --- | --- |
| 长辈（主视角） | 每天面对吃药、亲友通话、出门、给孩子报平安四类高频事务 | 看得清、点得准、听得懂、做完有成就感 |
| 子女（守护视角） | 远程为父母设置提醒，确认父母是否按时吃药、是否平安 | 设置省力、可回头修改、动态可见、成果可纪念 |
| 评委（体验视角） | 30 秒内体验全部功能 | 顶部一键切换双端视角，首屏即有可点数据 |

设计主张：把**适老化实用功能**与**游戏化趣味正反馈**融合——备忘不再是清单，而是一座会因为坚持而开花的「亲情花园」。

## 2. 设计原则

### 2.1 适老化硬性指标（不可回退项）

1. 基础字号三档：**标准 20px / 大 22px / 特大 25px**，只改根字号，全站 rem 尺度（文字、内边距、圆角、间距）联动放大；档位选择持久化到本机，任何屏宽都不得低于 20px。
2. 标题层级随根字号缩放：标准档实测页面主标题 42px（2.1rem）、卡片标题 32px（1.6rem）、弹窗主标题 42px。
3. 所有可点击控件高度 **≥60px**，主操作按钮 72–80px；实测页面无一个按钮低于 60px。
4. 高对比暖色：底色 `#FFFDF7`、正文 `#222222`，对比度 ≈15.6:1（超 WCAG AAA）。弱化文字统一使用 `--ink-mute: #6B6552`，实测对最浅背景 `#FFF0C4` 为 5.2:1，达标 AA（旧值 `#8A8266` 仅 3.3:1，已废弃）。
5. 大圆角（14–42px）+ 宽间距（卡片间 26px、区块间 22px），按钮彼此隔离，防止误触。
6. 键盘与读屏可达：首屏 skip-link 直达卡片区、弹窗 Tab 焦点陷阱、关闭后焦点归还触发按钮、`aria-pressed` 状态同步、`:focus-visible` 4px 蓝色描边。

### 2.2 游戏化三原则

1. **即时反馈**：一次操作同时给视觉（印章+粒子）、听觉（音效+语音）、数值（能量+100）三路反馈。
2. **可视化成长**：抽象的坚持被换算成植物四阶段成长，进度条永远指向"下一个可见目标"。
3. **可纪念的成果**：年度战绩海报把日常打卡升华为"战绩"，勋章给出社交话题。

## 4. 视觉规范

### 4.1 配色体系

| 用途 | 类别主色 | 卡片底 | 卡片描边 | 正文 |
| --- | --- | --- | --- | --- |
| 全局背景 / 正文 | — | `#FFFDF7` | — | `#222222` |
| 分区容器（顶部 / 标签条 / 设置面板） | — | `--bg-soft #FBF6EA` | `--line #E6DCC6` 2px | — |
| 花园分区 | — | `--bg-garden #F4F9F3` | `--line` 2px | — |
| 所有卡片与弹窗 | — | `#FFFFFF` | 三边 `--line` 2px + **左侧 10px 类别色条** | `#222222` |
| 💊 按时吃药 | `#C25A00` | — | — | 仅色条 / 标签 / 选中态 |
| 📞 亲友电话 | `#0B6E9E` | — | — | 同上 |
| 🚌 出行提醒 | `#146B3A` | — | — | 同上 |
| 💌 给孩子的留言 | `#A8325C` | — | — | 同上 |
| 品牌与选中态 | `--accent #6B4E00` | — | — | 反白 `#FFF` |
| 完成态 / 印章 | `#146B3A` / `#C0392B` | 白 | — | 白 / 红 |
| 弱化文字 | `--ink-mute #6B6552` | — | — | 对白底 5.8:1，达 AAA |

规则：

1. 卡片正文一律 `#222222`（对白底 15.9:1），类别信息**只**通过「左侧 10px 色条 + 类别标签文字色 + 选中态填充」三处编码，不再使用淡彩底与彩色描边。
2. 全站已无 `linear-gradient` / `radial-gradient`：分区底、进度条、勋章边框全部为单一色值；强调靠色相而非高光。
3. 类别主色用作 23px 粗体标签文字时实测 4.42:1——按 WCAG 大号文本（≥18.5px 粗体）标准达 AA；若日后把该标签缩小到正文级，需改用更深的类别色。
4. 不使用 `opacity` 表达"次要"，一律改用色值（见 §2.1 第 4 条）。
5. 图形只用**一套内联 SVG 精灵**（`index.html` 顶部 `<symbol id="ic-*">`，HTML 与 JS 均通过 `<use href="#ic-*">` 引用，现有 12 个：四类别、四阶段植物、品牌、`ic-sound` / `ic-check` / `ic-alert`）。形状只依赖两个变量：`currentColor`（跟随文字色，因此标签选中态"类别色底 + 白字"时图标自动反白，红色紧急按钮里的白十字也一样）与 `--bloom`（花/果的第二色，仅花园主图与信封爱心使用）。图标一律 `aria-hidden="true" focusable="false"`，不参与读屏朗读。
6. 页面底色叠一层 5% 浓度的单色噪点 SVG（`body` 的 `background-image`，200×200 平铺）作纸纹；它不承载信息，也不与任何色值比较对比度。
7. `--danger #A32020` 只出现在两处语义：通话弹窗的「挂断」与左栏的紧急求助大按钮。后者是全站唯一的大面积红底，实测白字对比 7.54:1（AA 大号文本、AAA 均通过）；紧急信息弹窗内部**不再**用红色描边或红色色条，只保留顶部一行红字小标题（对白底 7.41:1），避免把"需要帮助"渲染成"已经出事"。

### 4.2 降噪与质感规范（2026-11-17 起）

| 维度 | 收敛后的做法 |
| --- | --- |
| 色彩层次 | 一张卡片从「淡彩底 + 4px 彩边 + 大 emoji + 彩标签 + 白胶囊」五层，压到「白底 + 色条 + 彩标签 + 图标」 |
| 描边宽度 | 常规 2px（`--bw`）、触控控件 3px（`--bw-lg`）、卡片色条 10px（`--spine`）；旧的 4–5px 粗边全部下线 |
| 动画 | 仅保留一次性触发：`rise / slide-in / fade / bloom / stamp-drop / fall / track-pop`；`sway`（植物摇摆）、`float-deco`（装饰飘动）、`shine`（进度条斜纹流光）、`spin`（海报光斑旋转）已删除。页面静止时唯一的持续动画是通话弹窗的振铃扩散环 `pulse` |
| 动效触发 | 一次性动效一律"挂 class → 播完摘掉"，不常驻、不循环。入场错峰由 JS 加 `.board.is-entering`（只响首屏 / 筛选切换 / 视角切换，900ms 后自动摘），打卡与保存这类数据刷新不重播；能量数字用 rAF 补间并由 760ms 定时器兜底钉到终值；升级动画由 `addEnergy` 置 `pendingLevelUp`、`renderGarden` 消费后清零，跨标签页同步不会误播 |
| 图形 | 类别图标、四阶段植物、品牌标记、分类筛选与卡片操作按钮全部改为 SVG 精灵；花园区原有的 emoji 装饰层（🌿🌼🦋🍎🍇）整体删除，避免同一画面里"手绘图形 + 系统 emoji"两种画风打架。扩展功能轮次只往同一份精灵里加了第 12 个符号 `ic-alert`（紧急求助按钮的加号块），没有另起画风 |
| 强调色用量 | 两支强调色按语义分族，本轮没有新增色相：**暖棕 `--accent`** = "战绩数字"族与主操作（品牌主标题、`.btn-primary`、字号档选中态、"全部"筛选类别色、等待态 pill、阶段轨道"当前"档文字、海报标题 / `.stat .num` / 勋章标题）；**绿 `--good`** = "花园激励"族与成功态（花园 kicker、植物阶段名、`#energyNum` 能量数字、留言类别）。扩展功能轮次把 `.sum-num`（今天 N 件 / 已办妥 M 件）归进战绩族、`.sum-streak`（连续天数）归进激励族，正是借这两条既有分族让左栏一眼可读。另首次让 `--danger` 以大面积底色出现一次（紧急按钮，理由与实测对比见 §4.1 规则 7） |
| emoji | 只保留在**语义本身是表情/人脸**的位置：模式切换 👵🧑（两张脸差异比剪影更好认）、通话头像（按称呼匹配性别年龄）、勋章、撒花粒子。`听一听 / 我办妥了 / 一键呼叫` 三个高频按钮已换成 SVG 图标 + 纯文字 |
| 粒子 | 打卡全屏撒花 30 → 16 颗，按钮迸发 14 → 9 颗，升级补撒 24 → 14 颗；emoji 种类 8 → 4 |
| 阴影 | 双层叠加：`--shadow` = 1px 贴近 + 8px 20px 扩散（合计约 .05 + .06 透明度），`--shadow-lg` 用于浮层与悬停；选中态不再额外叠阴影 |

> 尺度放大机制（实测校准）：三档字号放大的是 rem 部分——文字、内边距、圆角、间距；而各按钮的 `min-height` 写的是 px 固定下限（60–80px），**不会**随根字号缩放，实际高度靠放大后的文字撑高。实测「特大」档下一键呼叫按钮高 147px（下限仍是 80px）。因此"触控目标一定同步变大"并不严谨：单行短文字的按钮可能仍停在 px 下限。若要真正等比，应把 `min-height` 改为 rem（见 §9 待办）。

## 5. 数据设计

### 5.1 存储

- 唯一键：`localStorage['suisuinian.memo.v1']`
- 首次打开（无该键）自动写入 4 条示例卡片与一份示例紧急求助信息，覆盖四大分类，保证"点开即可体验"。
- 写入失败（隐私模式 / 存储被禁）时捕获异常并 toast 提示，不中断交互。


`line2` / `line3` 的展示语义随 `type` 变化，由 `CATS[type].rowLabels` 决定标签文字：

| type | heading | line2 | line3 | phone |
| --- | --- | --- | --- | — |
| medicine | 药名 | 剂量与叮嘱 | 提醒时间 | — |
| phone | 亲友 | 方便时间 | （右上角时间胶囊） | 号码 |
| travel | 目的地 | 随身带 | 出发时间 | — |
| message | 卡片标题 | — | 时间胶囊 | — |

> 已知取舍：用统一的 `line2/line3` 而非按类型分字段，换取渲染与存储的简单；后续若要按类型做校验或提醒时间调度，应拆成结构化字段（见 §9）。
> 加载时 `migrate()` 会补齐缺失字段并把非法 `textSize` 归位为 `normal`，旧版本数据可无损升级。`emergency` 用 `Object.assign(seedEmergency(), s.emergency)` 逐键补齐：子女**故意清空**的字段存的是空字符串，键仍在，因此不会被示例值顶回来——只有老版本根本没有的键才落到示例默认值。

### 5.3 隔日重置规则

清空每张卡片的 `done/doneAt`（印章消失、按钮恢复可点），但 **`energy`、`checkins`、`feed`、`stats` 全部累计保留**。触发时机有三处，保证"页面整天开着也不会留旧印章"：

1. 加载时 `migrate()` 比对 `state.day`；
2. 每 30 秒轮询 `rolloverIfNewDay()`；
3. `visibilitychange`（标签页重新可见）与 `window focus` 时立即检查。

后两者命中时会重绘并 toast「新的一天，印章已清空」+ 语音播报。

### 5.4 跨标签页同步

监听 `window` 的 `storage` 事件：另一端（如子女模式标签页）写入后，本端重新读取状态并整体重绘，同时 toast「已同步另一端最新打卡动态」。演示方式：开两个标签页，一个长辈模式打卡，另一个子女模式的通知栏会实时冒出新动态。

### 6.1 双端视角一键切换

### 6.2 四大场景卡片

卡片为**白底 + 左侧 10px 类别色条**，色条颜色即类别（见 §4.1）；卡片内部不再出现第二种色彩表达，正文一律 `#222222`。

- 💊 吃药：药名 / 剂量与叮嘱 / 提醒时间，附温水送服温情提示。
- 📞 电话：整行超大「一键呼叫 女儿」（左侧 SVG 话筒图标），弹窗内头像随姓名智能匹配（女儿→👩、儿子→👨、奶奶→👵…）。
- 🚌 出行：目的地 / 出发时间 / 随身带清单，附"出门前看看天气"提示。
- 💌 留言：6 句大字短语（"今天按时吃药啦，别惦记"等），点一下即发送，已发送项转为绿色 ✓ 状态，无需打字。
- 时间胶囊改为**透明底 + 2px 细线**描边，不再是白色实心胶囊。
- 顶部大标签一键筛选，`aria-pressed` 同步，筛选后计数文案随之变化；选中态用类别主色实心填充 + 白字（降噪后不再叠加阴影与加粗边框）。

### 6.3 🌱 亲情暖心花园

能量来源：打卡 **+100**、发送留言 **+60**。

| 阶段 | 能量区间 | 主图形（SVG 精灵） | 第二色 `--bloom` |
| --- | --- | --- | --- |
| 小嫩芽 | 0–299 | `#ic-sprout` 双叶嫩芽 | 不用（纯绿） |
| 含苞待放 | 300–799 | `#ic-bud` 花苞 | `#D9679B` |
| 繁花盛开 | 800–1599 | `#ic-blossom` 五瓣花 | `#F291B4` |
| 硕果累累 | 1600+ | `#ic-fruit` 结果树 | `#C0392B` |

原来的 emoji 装饰层（🌿 / 🌼🦋 / 🍎🍇）已整体删除：植物本体改成手绘 SVG 后，同一画面里再叠系统 emoji 会出现两种画风打架，且果实、花瓣已经画进主图形，装饰层不再承载信息。

- 进度条显示"当前阶段 → 下一阶段"的完成度，文案给出**还差多少点**的具体目标（封顶阶段改为成就文案）。
- 布局：花园整体放在**第二行右栏**（与设置区左右并排，两者都在整行页面标题之下），内部改为植物舞台在上、能量与阶段轨道在下的单列；原"左 300px 舞台 / 右信息"两栏已取消，因为并排后每栏只有约 620px，两栏会让四阶段轨道挤成窄条。
- 进度条填充改为 `--good` 单色，删掉原三色渐变与 `shine` 斜纹流光；装饰 emoji 静态摆放（原 `float-deco` 上下飘、原 `sway` 植物摇摆均已删除）。
- 四阶段轨道条实时标记 已完成 / 当前 / 未到达；"当前"档不再常驻 `scale(1.05)` 放大，只用淡金底 + 描边表达；阶段刚跨过阈值时由 `track-pop` 关键帧给当前格做一次 0.55s 的缩放回弹（`is-pop` 类播完即摘）。
- 跨越阈值时：只保留一次 `bloom` 缩放回弹（`.plant-main` 0.6 → 1.35 → 0.95 → 1，0.9s）+ 补撒 14 颗粒子 + 语音播报；原外圈金色光晕（`box-shadow: 0 0 0 6px`）已删除——它在零动画页面上反而最抢眼。
- 升级反馈的传播路径：`addEnergy()` 只负责判定"阶段索引是否前进"，前进才置 `pendingLevelUp`；`renderGarden()` 在画完阶段图形后读取该标记并立即清零。之所以不用函数参数传递，是因为 `render()` 会无条件调用 `renderGarden()`，任何走完整渲染的入口（打卡、留言、跨标签页同步、恢复示例数据）都要自己记得传参——历史上正是这个原因，升级分支一直被 `render(false)` 写死成永不执行的死代码。用标记位后，外部同步来的能量变化不经过 `addEnergy()`，标记不置位，因此不会误播动画。

### 6.4 打卡正反馈时序

```
点「我办妥了」
  ├─ 卡片盖红印章（stamp-drop 0.45s，含 -14° 旋转与轻微回弹）
  ├─ 按钮变为「已办妥」并 disabled（避免重复领取能量）
  ├─ energy +100 → 阶段判定 → 跨阈值才置 pendingLevelUp，下一次渲染播放 bloom + track-pop 并补撒粒子、二次播报
  ├─ 能量数字 620ms 缓出补间滚到新值；reduced-motion / 页面隐藏 / 新旧值相同 三种情况直接写终值，另挂 760ms 定时器兜底
  ├─ 粒子：全屏撒花 16 颗 + 按钮原点迸发 9 颗（升级时补撒 14 颗，emoji 种类 4 种）
  ├─ 音效：WebAudio 四音上行短琶音（523→1046Hz）
  ├─ 语音：按分类的趣味夸夸语（rate 0.9，随机取一条）
  ├─ 写入 localStorage，并 push 一条通知栏动态
  ├─ 卡片不重播入场错峰（is-entering 只由首屏 / 筛选切换 / 视角切换挂载）
  └─ 另一端标签页经 storage 事件实时同步
```

补间过程只改可见文本，`aria-valuetext` 从一开始就写终值（"亲情能量 350 点，含苞待放"），读屏用户听到的是结果而不是逐帧跳动的数字。

已办妥卡片再次点击不会重复加分，只提示"明天再来领取新的能量"。

**卡片入场错峰**：`playEntrance()` 在 `#board` 上挂 `is-entering`，`.board.is-entering .card` 播放 0.46s 的 `rise`，第 2~5 张依次延迟 0.06 / 0.12 / 0.18 / 0.24s、第 6 张起统一 0.3s，900ms 后摘掉类。挂载前会先"移除 → 强制回流 → 添加"，让同一入口连续触发两次也能重头播。触发点只有三处：首屏启动、分类筛选切换、双端视角切换；打卡、发送留言、保存新卡片等数据刷新**不**触发，否则每点一次「我办妥了」四张卡都会重新跳一遍——这正是降噪轮次里被反馈为"闪烁"的原因。

### 6.5 语音朗读无障碍

- 全部朗读走浏览器原生 `window.speechSynthesis`，`lang = zh-CN`，自动挑选系统中文音色。
- 语速分级：朗读卡片内容 **0.78**（慢而清晰）、夸夸语与模式提示 **0.9**、欢迎语 **0.85**。
- 朗读文本按类型组装：类别 → 具体内容 → 下一步指引，例如"这是一条按时吃药提醒。药名 氨氯地平 5 毫克。每次 1 片 · 早饭后半小时温水送服。提醒时间 今天 08:00。听完以后，点右边的大按钮，我办妥了。"
- 电话号码**逐位转汉字**朗读（一 三 八 …），避免 TTS 把 `13800001234` 读成数字串。
- 每次朗读前先 `cancel()`，防止排队叠音；系统不支持 TTS 时降级为文字 toast。

### 6.10 键盘可达性与焦点管理

| 能力 | 实现 |
| --- | --- |
| 跳过导航 | 首个可聚焦元素为 `.skip-link`（默认藏在视口上方，`:focus` 时滑出），指向 `#board`，`#board` 带 `tabindex="-1"` 保证可被聚焦 |
| 弹窗焦点陷阱 | `trapTab()` 在 `#callOverlay` / `#reportOverlay` / `#emergencyOverlay` 内拦截 Tab，首尾循环；只统计 `offsetParent !== null` 的可见可聚焦元素 |
| 焦点归还 | `showOverlay()` 记录 `document.activeElement`，`hideOverlay()` 关闭后归还（元素仍存在时才归还），避免关闭后焦点掉回 body |
| 键盘关闭 | Esc 按 通话 → 海报 → 紧急求助 的优先级关闭当前浮层；点遮罩等同关闭 |
| 朗读中断 | 关闭海报与紧急求助弹窗时 `speechSynthesis.cancel()`，防止弹窗已关语音仍在念 |

### 6.11 今日概览 · 连续天数 · 一键播报

长辈侧左栏的一块白底小结（`.only-elder`，子女模式整块隐藏），把"我今天做到哪了"和"不用逐个点听一听"两件事一次解决。

- **今天 N 件事 · 已办妥 M 件**：数字用 `.sum-num`（标准档 34px）单独放大，随 `render()` 刷新，打卡、增删卡片、隔日重置都会立刻跟着变。
- **连续坚持 K 天**：`streakDays()` 把 `checkins` 的时间戳归成日期集合，从今天往前逐日回退计数。**今天还没打卡时从昨天起算**——否则白天打开永远显示 0 天，等于惩罚还没做的人，而 streak 类产品最常见的口径问题正是这里。文案分三档：0 天"办妥一张就从今天开始"、1 天"明天继续就成串啦"、≥2 天"已连续坚持 K 天，花园陪您走了 K 天"。
- **一键播报**：`speakToday()` 先念一句总览（日期 / 总件数 / 已办妥数），再按卡片顺序逐张调用现有的 `cardSpeechText()`，只念**还没办妥**的；全部办完则念一句总结。按钮文案在朗读中切成「别念了，停下」并置 `aria-pressed="true"`，再点一次即 `cancel()` 停止，`onend / onerror` 兜住自然结束。
- 播报走新增的 `voice.saySeq(list, onDone)`：`speechSynthesis` 自身会排队，所以**只在开头 `cancel()` 一次**，若像 `voice.say()` 那样每段都 cancel 就会把前一段打断，只剩最后一句。浏览器不支持 TTS 时 `saySeq` 返回 false，按钮状态当场回滚并降级为文字 toast，不会留下一个写着"停下"却什么都没在念的按钮。

### 6.12 🚑 紧急求助信息卡

养老场景里最实在的一块：长辈不舒服时不需要翻号码、不需要解释病史，一个大按钮把信息摊在屏幕上给身边的人看。

- 入口是左栏整行红色大按钮（`--danger` 底 + 白字，实测对比 7.54:1；`min-height: 72px`、字号 27px）。同一按钮两种文案：长辈侧「我不舒服」、子女侧「设置紧急求助信息」，用 `.only-elder` / `.only-child` 两个 span 切换，**不需要 JS 参与**，也不会出现"长辈看到'设置'二字不敢点"的情况。
- 六个字段由 `EMG_FIELDS` 单表驱动（联系人 / 电话 / 住址 / 血型 / 正在服用的药 / 过敏与既往情况），查看态与编辑态共用这张表，加字段只改一处。
- 弹窗内两套面板：`#emgView` 大字只读（值 30px/800，标签 21px），`#emgEdit` 复用设置面板的 `.field-rows` 样式（输入框 `min-height: 64px`）。子女侧点入口直接进编辑态，长辈侧点入口进查看态并聚焦「念给对方听」。
- 空字段不隐藏而是显式写「未填写 · 请在子女守护模式补充」并降一档字色，让缺口可见、可被补齐；隐藏字段会让人误以为系统没这个能力。
- 「念给对方听」用 `emergencySpeechText()` 组装，号码走既有的 `readablePhone()` 逐位读汉字；显示态则用 `spacedPhone()` 按 3-4-4 分组，方便照着拨。
- 保存走 `pushFeed('setup', …)`，子女侧通知栏留痕；编辑态的「返回查看」丢弃草稿（重新从 `state.emergency` 渲染），保存才落库——与卡片设置面板的行为一致。
- **隐私边界**：这组字段是全应用唯一涉及真实个人健康信息的地方，仍然只写本机 `localStorage`，不联网、不上传、不共享；页脚与弹窗内都写了这句声明。清除站点数据即彻底消失。
- 演示辅助：页脚「补一段上周打卡（演示）」给最近三天各补一条**真实结构**的吃药打卡并按 `+100` 走 `addEnergy()`，因此 streak、能量、花园阶段、年度战绩四处口径始终一致；已存在记录的日期会跳过，重复点击不会翻倍。补历史只用于演示，不进入正式数据流。

## 7. 技术选型与约束

| 决策 | 理由 |
| --- | --- |
| 三个静态文件、无构建 | 比赛要求"无需后端服务器即可在浏览器直接运行"，双击 `index.html` 即演示，零环境成本 |
| `js/app.js` 用单个 IIFE 传统脚本，**不用 ES Modules** | `file://` 协议下 `import` 受 CORS 限制会直接报错，传统脚本才能双击运行 |
| 目录仅按 `css/ js/ docs/` 分层 | 保持相对路径引用，不引入任何加载风险 |
| 字号三档只改根字号 | 一处改动驱动全站 rem 联动，避免维护两套尺寸表；触控目标随字号同步变大才是真适老 |
| 弱化文字用色变量 `--ink-mute` 而非透明度 | 叠加 `opacity` 会把对比度拉到 AA 以下，改色值才可控 |
| 语音用 `speechSynthesis`、音效用 WebAudio | 均为浏览器原生能力，不联网、不下载、不上传任何信息 |
| 定时器统一登记（`callTimers` / `callIntervals`） | 通话弹窗可反复打开/挂断，必须保证旧定时器全部清理，否则计时错乱 |
| 跨日检查用「加载 + 30s 轮询 + 可见性/聚焦」三重触发 | 长辈设备可能整天不刷新页面，只靠加载判断会留着一天的旧印章 |
| 尊重 `prefers-reduced-motion` | 该偏好下跳过粒子动画、平滑滚动、入场错峰与数字补间，动效敏感长辈也能安全使用 |
| 一次性动效用"挂 class + 定时摘除"而非 CSS 常驻 | CSS 里写 `animation` 会在每次重排后重播；本项目的卡片是 `render()` 全量重建的，常驻写法等于每点一次打卡就整屏闪一遍。摘除时机取"最长延迟 + 动画时长"再留余量（0.3s + 0.46s → 900ms），宁可晚摘不可早摘 |
| 数字补间用 `requestAnimationFrame` 但必须配 `setTimeout` 兜底 | rAF 在不渲染的表面上永远不回调（后台标签页、最小化窗口、内嵌 0×0 面板），只靠它数字会停在旧值而 `localStorage` 已经是新值，读起来像"打卡没加分"。补间 620ms、兜底 760ms，正常路径下兜底只重复写一次同一个终值 |
| 升级标记用模块级变量而非 `renderGarden(布尔)` 参数 | `render()` 无条件调用 `renderGarden()`，用参数传意图要么每个入口都记得传、要么就被默认值写死；历史上正是后者让升级动画分支成为永不执行的死代码。标记位由唯一的加分函数 `addEnergy()` 置位、由唯一的消费点清零，读不到状态的外部更新自然不误播 |
| 无框架、无第三方库 | 代码体量可控，评委可直接读源码理解实现 |
| 视觉降噪也**不**引入 CSS 框架 | 部署上线只解决了"CDN 需要联网"这一条，另外两条仍在：本次是删除性改动（去渐变、去常驻动画、压色彩层次），框架只提供增量；Tailwind Play CDN 官方标注不宜用于生产，且浏览器内即时编译会给首屏加一次 JS 执行。真要用 Tailwind 就得本地 build 后提交产物，等价于"仓库里一份静态 CSS"，运行时仍是零依赖 |
| 协作者的三档字号机制优先于框架默认尺度 | `html[data-textsize]` 只改根字号即可让全站 rem 联动；框架自带的设计尺度表会与之争夺控制权，迁移中极易把"特大档"退回固定 px，丢掉硬指标 |
| 配色与尺度固化为 `:root` token 表（§4.1） | 想要的其实是框架的"一致性"，而 token 表能在零依赖前提下给到：改一个变量即可全站收敛，不需要引入任何文件 |
| 图形用**单个内联 SVG 精灵**，不引图标库、不用外部 `.svg` 文件 | 零依赖与 `file://` 双击可运行是硬约束：图标库要么联网要么进构建；外链 `.svg` 在 `file://` 下 `<use>` 会被 CORS 拦。同文档内的 `<use href="#id">` 不受限，且形状用 `currentColor` 绘制，选中态反白不用二次描图 |
| 纸纹用 data-URI 单色噪点，不用位图素材 | 一张 200×200 平铺，不增加文件、不产生网络请求，也不会像照片纹理那样压过文字对比度 |
| 连续天数**今天没打卡就从昨天起算** | 若严格从"今天"开始数，长辈白天打开页面永远看到 0 天，等于在最需要鼓励的时段惩罚还没做的人，晚上补打卡又突然变 1。改成"最近一段未断的串"后，白天显示昨天为止的成果、打卡后自然含今天。代价是它表达的不是"今天已完成"，已写进 §9 限制 8 |
| 多天朗读用 `voice.saySeq()`，只在开头 `cancel()` **一次** | `speechSynthesis` 本身有队列，逐段 `say()` 会自动接上；若沿用单次播报那种"每段先 cancel"，等于每段都打断上一段，最后只剩最后一句——这正是第一版实测出来的现象。cancel 一次 + 末条 `onend/onerror` 复位，才既连贯又能收尾。不支持 TTS 时 `saySeq` 返回 `false` 让调用方回滚按钮态，不留一个"写着停下却什么都没念"的按钮 |
| 演示补历史走 `addEnergy()` 而不是直接改 `state.energy` | streak、能量数字、花园阶段、年度战绩四处都从 `checkins` / `energy` 推导。补录若绕过加分函数，就会出现"连续 4 天但花园还是嫩芽"的自相矛盾，答辩时一戳就破。按每条 +100 走同一条路径，四处自然一致；同时按日期去重保证重复点击不翻倍 |
| 紧急信息空字段显式写"未填写"而不是隐藏该行 | 隐藏会让人以为产品没有这个能力，也会让子女不知道少填了什么；显式占位 + 降一档字色，把缺口变成可补齐的清单。数据侧用 `Object.assign(seed, saved)` 的**按 key 合并**，因此"用户主动清空"（key 存在、值为空）会保留为空，只有旧数据缺 key 才回落示例值 |
| 一个按钮两种文案用 `.only-elder` / `.only-child` 两个 span，而不是 JS 改 `textContent` | 全站视角显隐本来就由 `body[data-mode]` 的 CSS 驱动（`display: none !important`）。再引入一处 JS 赋值就要在 `applyMode()` 里维护第 N 个特例，还会出现"切了视角文案没跟上"的时序问题；纯 CSS 与其余显隐项同源，天然一致 |
| 紧急求助按钮的图标进同一份 SVG 精灵（第 12 个符号 `ic-alert`） | 红底白十字若用系统 emoji（🚑）会出现"红色按钮 + 彩色贴纸"的割裂；用 `currentColor` 画的符号在红底上自动反白，与全站图标同一支笔法 |

### 2026-11-17 · 移动端适配与响应式布局

- 需求来源：用户——"现在开始做移动端适配 + 响应式布局"。
- 问题与动机：
  1. 原有断点只有 1080 / 720 两级，手机窄至 320px、字号放到「特大」档（根字号 25px）时，7 列日历、双列模式切换、5 个筛选大按钮、卡片双列操作键都会挤压或换行失控。
  2. 弹窗用 88vh 居中，iPhone 刘海与底部手势区会吃掉边缘；筛选条在手机上若自然换行，5 个大按钮会占满首屏，把卡片推到很下面。
  3. 打卡印章的落下动画会瞬时放大到 2.1 倍，在窄屏上短暂撑出横向滚动条。
- 修改方案：
  1. **视口与安全区**：`viewport-fit=cover` + `theme-color="#FFFDF7"`；`.app`、`.overlay`、`.toast` 接入 `env(safe-area-inset-*)`，其中 `.app` / `.overlay` 用 `max()` 保留非刘海设备的最小边距。
  2. **三档断点**：≤1080 单列并把花园改成左右分栏（阶段条改 2×2 防止文字折行）；≤720 手机竖屏——页头日期独占一行、设置区按钮通栏、卡片单列、日历紧凑化、弹窗近全屏内部滚动、页脚工具按钮通栏；≤400 小屏再收一轮边距。
  3. **模式切换**：≤560px 由双列改竖排，长按钮名不再挤成两行。
  4. **筛选条**：≤720px 改为单行横向滑动（`scroll-snap` + 隐藏滚动条），保留 60px 触控高度，下一项露出半截作为可滑提示。
  5. **日历**：月份独占一行、翻月按钮各占一半；7 列间距 4px；日格高度 `clamp(44px, 12vw, 62px)`、字号 `clamp(.85rem, 4.2vw, 1.05rem)`，320px + 特大档仍完整显示。
  6. **防横向溢出**：`.app > * { min-width: 0 }`；卡片与通知文本 `overflow-wrap: anywhere`；`html { overflow-x: clip }`（`overflow-x: hidden` 兜底）吸收印章缩放动画的瞬时外扩。
  7. **触屏细节**：按钮 `touch-action: manipulation` 并去掉 tap 高亮；`@media (hover: none)` 清除 hover 位移/阴影残留；主按钮保持 ≥60px 高度红线。
- 影响文件：`index.html`（viewport / theme-color）、`css/styles.css`（基础规则 + 重写 ≤720 断点，新增 ≤560 / ≤400 / `hover: none`）、`docs/DESIGN.md`（本条）。
- 验证方式与结果：临时 iframe 检测页覆盖 **320 / 360 / 375 / 414 / 768 / 1024px × 标准 / 大 / 特大** 共 18 种组合，分别检测主页面、打卡后印章、紧急求助弹窗、年度海报、子女设置面板的 `documentElement.scrollWidth` 与越界元素，结果全部无横向溢出；另在 320 / 375px 截图核对了模式竖排、日历、横向筛选条、单列卡片、印章与弹窗布局；浏览器控制台零消息。

### 2026-11-17 · 左栏扩展功能：今日概览 + 一键播报、连续坚持天数、🚑 紧急求助信息卡

- 问题与动机：
  1. 标题提升为整行后，左栏只剩"视角切换 + 报告 / 字号"，中下部空出一大片；而原本那行说明（`.mode-tip`："大图标、大按钮，只需两下手指就能听完、办妥"）只是把界面已经表达的事复述一遍，用户明确要求删掉。删掉后空位应当放**能少一次点击的东西**，而不是再放一句口号。

  1. **删净 `.mode-tip`**：HTML 段落、`applyMode()` 里对 `#modeTip` 的赋值、CSS 规则三处一并移除（`grep -rn "mode-tip\|modeTip"` 全站 0 命中）。第一次删除时误把 CSS 规则复制成两份，第三次编辑才清干净——已作为经验记录：删除声明块时锚点要覆盖到下一个选择器。
  2. **今日概览**（详见 §6.11）：左栏新增 `<section class="today-summary only-elder">`，两枚计数（`#sumTotal` / `#sumDone`）+ 连续天数 `#sumStreak` + 一个通栏「把今天的事念给我听」。`renderSummary()` 追加在 `render()` 末尾，与卡片同一批刷新，不需要单独的事件。
  3. **一键播报**：`speakToday()` 先念一句总览、再逐张复用现有 `cardSpeechText()`；配套 `voice.saySeq(list, onDone)` —— **只在开头 `cancel()` 一次**，把多条 `SpeechSynthesisUtterance` 交给 `speechSynthesis` 自动排队，在最后一条的 `onend / onerror` 上复位按钮；不支持 TTS 时返回 `false`，调用方回滚文案与 `aria-pressed`，避免"按钮说在念、其实没声音"。按钮双态（"把今天的事念给我听" ↔ "别念了，停下"）由 `setSpeakLabel()` 统一维护。
  4. **连续天数**：抽出公共日期键 `dayKey()` / `todayKey()`（跨日重置与 streak 共用同一套键，不会出现两处对"今天"的理解不一致）；`streakDays()` 把 `checkins[].at` 归合成日期集合后从今天逐日回退，**今天还没打卡就从昨天起算**。文案分三档，0 天时不写"连续 0 天"。
  5. **演示补录**：页脚新增 `#historyBtn` → `seedHistoryDemo()`，给最近三天各补一条**真实结构**的吃药打卡（已有记录的日期跳过）并逐条 `addEnergy(100)`，让 streak、能量、花园阶段、年度战绩四处口径始终一致；重复点击不翻倍。

## 9. 已知限制与后续候选

**当前限制（答辩时需如实说明）**

1. 「远程为父母添加卡片」在无后端前提下是**同浏览器双视角**演示；真实跨设备同步需要账号与消息通道。
2. 模拟通话不实际拨号，仅动画 + 音效 + 语音提示。
3. 语音音色依赖操作系统内置 TTS；若系统缺少中文语音包，可能静音（已做不支持时的文字降级）。
4. 卡片没有到点提醒能力（无 `Notification` / 定时调度），当前是"打开即见"的备忘形态。
5. 「特大」档（25px 根字号）下长文案卡片会变高，尚未逐条排版复核。
6. 无自动化测试，质量保障依赖手工走查清单。
7. 🚑「紧急求助信息」本质是**给身边人看的一张纸**：不自动拨号、不发短信、不定位，只做大字展示 + 一键朗读。真要一键呼叫需要系统能力（`tel:` 在桌面浏览器无意义），且会突破"不联网、纯前端"的定位。
8. 连续天数只统计"有打卡记录的日期"，无法感知长辈是否打开过页面；今天尚未打卡时从昨天起算（口径见 §6.11），所以它表达的是"最近一段没断的串"，而不是"今天已完成"。

**后续候选（等需求确认后再实施，不提前动代码）**

- ⚠️ **控件宽度与动效观感需在真实视口下复核**：微动效轮次已重新采集高度硬指标（`.act` 72px、呼叫键 80px、根字号 20px、`#board-title` 34px，均与 §4.3 一致），但内嵌浏览器面板 `window.innerWidth === 0`，宽度、换行与错峰跳动/数字补间的实际观感仍需在可见窗口目视确认。
- 把各按钮的 `min-height` 由 px 改为 rem（如 `.act` 3.6rem、`.btn` 3rem），让「大 / 特大」档真正等比放大触控目标，而不是只靠文字撑高。
- `.skip-link` 加 `white-space: nowrap`，解决极窄视口下被挤成竖排窄条（详见 §8 的 2026-11-16 待观察项）。
- 按类型拆分结构化字段（如 `medicine.dose/time`），支持字段校验与提醒时间调度。
- 接入 `Notification` API + 到点检查，实现真正的定时提醒（仍保持纯前端）。
- 留言支持录音回放与语音转文字，进一步降低打字门槛。
- ~~花园增加"连续坚持天数" streak~~ —— 已在扩展功能轮次实现（§6.11，显示在今日概览里而非花园面板）。剩余的候选是**枯萎/浇水隐喻**：目前 streak 只做正向陈述，断签不清零能量也不改变植物形态，要真正引入"枯萎"需要先确认长辈侧不会因为漏打卡产生挫败感（详见 §8 的扩展功能轮次记录）。
- 「补一段上周打卡」目前只在页脚以"演示"名义提供。若要作为正式功能，需要一个可自选日期的补录面板，并决定补录是否计入年度战绩——本轮为避免两处口径打架，直接复用了 `addEnergy()`，所以**是**计入的。
- 导出年度战绩图片（Canvas 绘制）替代截图/PDF。
- 三档字号下的排版复核与回归清单（尤其长药名、多携带物品、特大档 + 窄屏叠加时）。
- 类别标签若需缩小字号或减重，先换更深的类别主色再调（当前 4.42:1 只在 23px/800 下满足 WCAG 大号文本 AA）。
- 画风统一收尾：勋章、通话头像、撒花粒子目前仍是 emoji（语义本身是"人脸 / 表情 / 庆祝物"，见 §4.2）。若评委或用户仍觉得不统一，可为这三类再补一组 SVG，但通话头像涉及性别年龄匹配，emoji 的辨识度更高，建议先收反馈再动。
- SVG 形状现在是代码手绘的几何体（圆角矩形 + 圆弧），够干净但不是插画级精度；要更精致需引入位图或第三方图标集，与"零依赖 + `file://` 双击"冲突，属于需要单独决策的取舍。
